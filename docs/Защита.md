## 1. Что такое Робот и его API

Робот живёт на **клетчатом поле**. Между клетками (и по краю поля) могут стоять **стенки**. В клетках могут стоять **маркеры**. Библиотека — `HorizonSideRobots`.

### Что умеет Робот

| Вызов | Что делает |
|---|---|
| `Robot("file.sit", animate = true)` | создать робота на поле из файла; `animate = true` — рисовать окно с анимацией (нужен `GLMakie`) |
| `move!(robot, side)` | шаг на одну клетку в сторону `side`. Если там стенка — **ошибка** |
| `isborder(robot, side)` | есть ли стенка с этой стороны от клетки Робота (`true`/`false`) |
| `putmarker!(robot)` | поставить маркер в текущую клетку |
| `ismarker(robot)` | есть ли маркер в текущей клетке |

Больше Робот **ничего не знает**: ни своих координат, ни размеров поля. Всё, что нужно (сколько шагов сделал, в каком ряду), программа считает **сама**.

### Стороны света

`HorizonSide` — перечисление из четырёх значений. Порядок важен:

| Сторона | Число `Int(side)` |
|---|---|
| `Nord` (север, вверх) | 0 |
| `West` (запад, влево) | 1 |
| `Sud` (юг, вниз) | 2 |
| `Ost` (восток, вправо) | 3 |

Порядок идёт **против часовой стрелки**. Поэтому поворот — это арифметика по модулю 4:

```julia
inverse(side) = HorizonSide(mod(Int(side) + 2, 4))   # противоположная сторона
left(side)    = HorizonSide(mod(Int(side) + 1, 4))   # налево от направления движения
right(side)   = HorizonSide(mod(Int(side) + 3, 4))   # направо от направления движения
```

Примеры: `left(Nord) = West`, `left(Ost) = Nord`, `left(West) = Sud`, `inverse(Ost) = West`, `right(Nord) = Ost`.

> [!tip] Запомни
> «Налево от направления движения» — это **не** «налево на экране». Если Робот идёт на `Ost`, то налево от него — `Nord`. Именно так `left` используется при обходе стенок.

### Виды полей в задачах

- **Ограниченное без перегородок** — только внешняя рамка (задачи 1, 2, 4, 7, 8, 10).
- **Ограниченное с перегородками** — внутри изолированные отрезки и прямоугольники, которые **не касаются** друг друга и внешней рамки (задачи 3, 6, 9, 12).
- **Ограниченное с одной внутренней рамкой** — один прямоугольник внутри (задачи 5, 11).
- **Неограниченное** — поле «бесконечное», границ нет (задачи 13, 14, 15).

> [!important] Почему важно слово «изолированные»
> Если перегородки не касаются рамки и друг друга, то:
> 1. нижний ряд, верхний ряд, левый и правый столбцы **всегда свободны**;
> 2. любую перегородку можно **обойти** по кругу.
> На этом держится почти всё: `to_corner!`, змейка, возврат в исходную клетку.

## 2. Главные идеи, на которых всё построено

### 2.1. Инвариант — «вернуть Робота на место»

Почти каждая задача требует: **после работы Робот стоит там, где стоял**. Приём один и тот же:

1. запомнить, **сколько шагов** сделали (числа, не позиции);
2. сделать работу;
3. пройти обратно столько же шагов.

### 2.2. Решение «сверху вниз»

Главная функция читается как план из 3–4 строк. Каждая строка — вызов вспомогательной функции со своим смыслом:

```julia
function task2!(robot)
    num_west, num_south = to_corner!(robot)          # 1. в угол, запомнив путь
    walk_perimeter!(robot, mark_cell!)               # 2. сама работа
    from_corner!(robot, num_west, num_south)         # 3. назад
end
```

### 2.3. Функции как аргументы (`act`)

Обход (периметр, крест, змейка) **один и тот же**, а действие в клетке разное: поставить маркер или посчитать маркеры. Поэтому обход принимает функцию `act`:

```julia
mark_cell!(robot)   = (putmarker!(robot); 0)   # поставить маркер, вернуть 0
count_marker(robot) = Int(ismarker(robot))     # 1 если маркер есть, иначе 0
```

Обе функции **возвращают число**. Обход складывает эти числа и возвращает сумму:

- `walk_perimeter!(robot, mark_cell!)` — ставит маркеры, сумма равна 0, её игнорируем;
- `walk_perimeter!(robot, count_marker)` — считает маркеры, сумма — это ответ.

Один обход — два применения. Это и есть главный приём «чистого» кода в работе.

### 2.4. Именованные кортежи вместо мутабельных структур

Функции, которым надо вернуть несколько чисел, возвращают `(num_west = 3, num_south = 2)`.

```julia
num_west, num_south = to_corner!(robot)   # распаковка по именам
snake = walk_snake!(robot, count_marker)
snake.total    # обращение по имени
snake.num_up
```

Кортеж **неизменяемый** — после создания его нельзя поменять (по лекции 4 — без мутабельных структур). В задаче 15 позиция Робота — тоже именованный кортеж `(x = 0, y = 0)`; каждый шаг возвращает **новый** кортеж.

### 2.5. Перегрузка `move!`

```julia
import HorizonSideRobots: move!

function move!(robot, side, num_steps)    # то же имя, но 3 аргумента
    for _ in 1:num_steps
        move!(robot, side)
    end
end
```

Имя `move!` — одно, а методов два: `move!(robot, side)` из библиотеки и наш `move!(robot, side, num_steps)`. Julia выбирает по **числу аргументов** (множественная диспетчеризация). Чтобы **добавить** метод к чужой функции, её надо **импортировать** (`import ... : move!`); одного `using` недостаточно.

### 2.6. Договорённость об именах

- Знак `!` в конце — функция **меняет состояние** (Робота, поле).
- `num_*` — число шагов/штук (`num_west`, `num_steps`, `num_up`).
- `walk_*` — обход чего-то.
- `move_*` — перемещение.

## 3. Вспомогательные функции — разбор по строкам

> [!note]
> Здесь каждая функция разобрана **один раз**. В задачах дальше они только вызываются.

### 3.1. `move!(robot, side, num_steps)` и `move_to_frame!(robot, side)`

```julia
function move_to_frame!(robot, side)
    while !isborder(robot, side)
        move!(robot, side)
    end
end
```

Идти в сторону `side`, пока впереди нет стенки. Работает «до упора». Используется там, где путь свободен (перегородок на нём нет).

### 3.2. `walk_to_frame!(robot, side, act)`

```julia
function walk_to_frame!(robot, side, act)
    num_steps, total = 0, 0
    while !isborder(robot, side)
        move!(robot, side)
        total += act(robot)       # act — ПОСЛЕ шага, в стартовой клетке не вызывается
        num_steps += 1
    end
    return (num_steps = num_steps, total = total)
end
```

- Идёт до рамки, после **каждого шага** вызывает `act`.
- Возвращает сколько шагов сделал и сумму `act`.
- **Важно:** `act` не выполняется в клетке, из которой вышли. Поэтому в кресте центр не обрабатывается.

### 3.3. `walk_kross!(robot, act)` — крест

```julia
function walk_kross!(robot, act)
    total = 0
    for side in (Nord, West, Sud, Ost)
        ray = walk_to_frame!(robot, side, act)        # дошли до края луча
        move!(robot, inverse(side), ray.num_steps)    # вернулись в центр
        total += ray.total
    end
    return total
end
```

Четыре луча. Каждый: дойти до рамки с `act`, вернуться ровно на `num_steps` назад. После цикла Робот в центре.

### 3.4. `walk_perimeter!(robot, act)` — периметр

```julia
function walk_perimeter!(robot, act)
    total = 0
    for side in (Nord, Ost, Sud, West)
        while !isborder(robot, side)
            total += act(robot)       # act ДО шага
            move!(robot, side)
        end
    end
    return total
end
```

Стартует из **юго-западного** угла. Идёт север → восток → юг → запад.

Почему каждая клетка обрабатывается ровно один раз:

- `act` вызывается **до** шага, то есть в клетке, которую сейчас покидаем.
- Угол, в котором закончили сторону, не обрабатывается в этой стороне, а обрабатывается в **начале** следующей.
- Стартовый (юго-западный) угол обработан в начале стороны `Nord`; в конце стороны `West` Робот в него приходит и там цикл заканчивается без `act`.

Итог: все клетки периметра по одному разу, Робот снова в юго-западном углу.

### 3.5. `along_wall!(robot, side, d)`

```julia
function along_wall!(robot, side, d)
    num_steps = 0
    while isborder(robot, side) && !isborder(robot, d)
        move!(robot, d)
        num_steps += 1
    end
    return num_steps
end
```

«Идти вдоль стены». Стена стоит со стороны `side`, идём в направлении `d` (перпендикулярном). Идём, пока стена **не кончилась** (`isborder(side)`) и **путь не закрыт** (`!isborder(d)`). Возвращает число шагов.

### 3.6. `pass_wall!(robot, side, d, num_steps)`

```julia
function pass_wall!(robot, side, d, num_steps)
    move!(robot, side)                       # шагнуть «за» конец перегородки
    num_advance = 1
    while isborder(robot, inverse(d))        # вдоль стороны прямоугольника
        move!(robot, side)
        num_advance += 1
    end
    move!(robot, inverse(d), num_steps)      # вернуться на исходную линию
    return num_advance
end
```

Вызывается, когда `along_wall!` довёл Робота до конца перегородки. Теперь стены в направлении `side` уже нет:

1. Шаг `side` — прошли мимо конца перегородки.
2. Пока с обратной стороны (`inverse(d)`) стена — идти дальше: так проходим вдоль стороны **прямоугольника** (у отрезка этой стены нет — цикл не выполнится).
3. Вернуться на `num_steps` назад — на ту линию, с которой начали.
4. Вернуть, на сколько клеток продвинулись в направлении `side`.

### 3.7. `move_bypass!(robot, side)` — шаг с обходом

```julia
function move_bypass!(robot, side)
    if !isborder(robot, side)
        move!(robot, side)
        return 1
    end
    d = left(side)                               # обходить будем налево
    num_steps = along_wall!(robot, side, d)
    if isborder(robot, side)                     # стена тянется до рамки — это внешняя рамка
        move!(robot, inverse(d), num_steps)
        return 0
    end
    return pass_wall!(robot, side, d, num_steps)
end
```

Три случая:

1. **Стены нет** — обычный шаг, вернуть 1.
2. **Стена — внутренняя перегородка**: идём вдоль неё до конца (`along_wall!`), обходим (`pass_wall!`), возвращаем на исходную линию. Вернули, на сколько клеток продвинулись (для прямоугольника больше 1).
3. **Стена — внешняя рамка**: `along_wall!` остановится у угла, а стена `side` всё ещё стоит. Тогда возвращаемся назад и возвращаем `0` — «дальше идти некуда».

Версия с числом: `move_bypass!(robot, side, n)` — `n` вызовов подряд.

> [!tip] Различение «перегородка» и «рамка»
> Перегородки изолированы (не касаются рамки). Значит, если идти вдоль стены и она **не кончается** — это рамка.

### 3.8. `to_corner!(robot)` — в юго-западный угол

```julia
function to_corner!(robot)
    num_west, num_south = 0, 0
    at_frame = false
    while !at_frame
        if !isborder(robot, West)
            move!(robot, West)
            num_west += 1
        else
            num_south = along_wall!(robot, West, Sud)
            at_frame = isborder(robot, West)
            if !at_frame
                pass_wall!(robot, West, Sud, num_south)
                num_west += 1
            end
        end
    end
    return (num_west = num_west, num_south = num_south)
end
```

Алгоритм: идём на запад. Упёрлись в стену — идём **вдоль неё на юг**.

- Если стена **кончилась** до дна — это перегородка. Обходим (`pass_wall!`), оказываемся на том же ряду западнее, снова идём на запад. Счётчик `num_west` +1 (считаем **вызовы**).
- Если мы спустились **до самого низа**, а стена слева всё ещё стоит — это внешняя рамка. Тогда Робот уже **в юго-западном углу**, и цикл заканчивается.

Что возвращает: `num_west` — сколько «шагов на запад с обходом» сделано, `num_south` — на сколько клеток спустились **в самом конце** вдоль рамки. А это ровно номер исходного ряда (считая снизу с нуля), потому что все обходы возвращали Робота на исходный ряд.

#### Разбор на примере

```
 y=3   .   .   .   .   .
 y=2   .   .   |   .   R        R в (3,2); перегородка — между x=1 и x=2,
 y=1   .   .   |   .   .        ряды y=1 и y=2
 y=0   .   .   .   .   .
      x=0  1   2   3   4
```

| Шаг | Что происходит | Позиция | num_west |
|---|---|---|---|
| 1 | West, стены нет | (2,2) | 1 |
| 2 | West — стена. `along_wall!` спускает на юг: (2,1), (2,0) | (2,0), num_south=2 | 1 |
| 3 | Стена слева кончилась. `pass_wall!`: шаг West (1,0), затем вверх на 2 | (1,2) | 2 |
| 4 | West, стены нет | (0,2) | 3 |
| 5 | West — рамка. `along_wall!` спускает до (0,0), num_south=2 | (0,0) | 3 |
| 6 | Стена слева всё ещё есть → `at_frame = true` | (0,0) | 3 |

Результат `(num_west = 3, num_south = 2)`.

### 3.9. `from_corner!(robot, num_west, num_south)` — назад

```julia
function from_corner!(robot, num_west, num_south)
    move!(robot, Nord, num_south)             # вверх вдоль рамки (она свободна)
    move_bypass!(robot, Ost, num_west)        # num_west шагов на восток с обходом
end
```

Обратный путь: сначала вверх по свободному левому столбцу на исходный ряд, затем на восток **столько же раз**, сколько шли на запад. Обход перегородок происходит так же, как при движении туда, поэтому Робот попадает ровно в исходную клетку (проверено в примере выше: из (0,2) три вызова `move_bypass!` приводят в (3,2)).

> [!warning] Частая путаница
> `num_west` — это число **вызовов** `move_bypass!`, а не число клеток. Через прямоугольник один вызов продвигает на несколько клеток.

### 3.10. `walk_snake!(robot, act)` — обход поля змейкой

```julia
function walk_snake!(robot, act)
    total = act(robot)                              # стартовая клетка (юго-западный угол)
    row = walk_to_frame!(robot, Ost, act)           # нижний ряд — он свободен
    width = row.num_steps                           # ширина поля − 1
    total += row.total
    x, side, num_up = width, West, 0                # x — текущий столбец
    while !isborder(robot, Nord)
        move!(robot, Nord)                          # подняться на ряд выше
        num_up += 1
        total += act(robot)
        target = side == Ost ? width : 0            # куда идти по этому ряду
        while x != target
            k = move_bypass!(robot, side)           # k — на сколько клеток продвинулись
            x += side == Ost ? k : -k
            total += act(robot)
        end
        side = inverse(side)                        # в следующем ряду — в обратную сторону
    end
    return (num_up = num_up, total = total)
end
```

Схема движения:

```
 ряд 3   ←←←←←←←←←←←←   (идём на запад)
          ↑
 ряд 2   →→→→→→→→→→→→   (идём на восток)
                  ↑
 ряд 1   ←←←←←←←←←←←←
          ↑
 ряд 0   S→→→→→→→→→→→   (S — старт, юго-западный угол)
```

Что важно понимать:

- **Ширина** определяется по нижнему ряду (он свободен) — по нему идём без обходов.
- **Столбец `x`** считается, а не опрашивается у Робота: на каждый вызов `move_bypass!` прибавляется `k` (или вычитается).
- Подъём на следующий ряд происходит у **края поля**, где столбец свободен от перегородок.
- `act` вызывается в клетке после шага — на каждой «посадочной» клетке ряда.
- Клетки, мимо которых Робот **проходил** при обходе перегородки, тоже будут пройдены: они лежат в соседнем ряду и обрабатываются на его проходе.
- Клетки внутри прямоугольной перегородки **недоступны** — их и не должно быть в ответе.
- Условие остановки: `isborder(robot, Nord)` проверяется **после** ряда, поэтому верхний ряд тоже обработан.

Возвращает `num_up` (на сколько рядов поднялись, высота − 1) и `total`.

### 3.11. `back_from_snake!(robot, num_up, num_west, num_south)`

```julia
function back_from_snake!(robot, num_up, num_west, num_south)
    move_to_frame!(robot, West)                   # верхний ряд свободен — в левый столбец
    move!(robot, Sud, num_up - num_south)         # вниз до исходного ряда
    move_bypass!(robot, Ost, num_west)            # вправо с обходом
end
```

Не возвращаемся в угол (дорого и не нужно): в верхнем ряду идём до западной рамки, спускаемся по свободному левому столбцу до исходного ряда (`num_up - num_south` шагов: от верхнего ряда `num_up` вниз на ряд `num_south`) и идём на восток.

### 3.12. `move_to_inner_frame!(robot)` — найти внутреннюю рамку

```julia
function move_to_inner_frame!(robot)
    side = Ost
    while !isborder(robot, Nord)         # змейкой, пока над головой не появится стена
        if isborder(robot, side)
            move!(robot, Nord)
            side = inverse(side)
        else
            move!(robot, side)
        end
    end
    while isborder(robot, Nord)          # затем налево до конца нижней стороны рамки
        move!(robot, West)
    end
end
```

Старт — юго-западный угол. Ищем прямоугольник змейкой: идём по ряду; упёрлись в край — поднимаемся и идём обратно. Как только **над** Роботом появилась стена — это нижняя сторона рамки. Идём на запад вдоль неё, пока стена над головой не кончится. Итог: Робот в клетке **по диагонали** от левого нижнего угла рамки (на ряд ниже и на столбец левее самой рамки).

### 3.13. `walk_around_inner!(robot, act; skip_frame = false)` — обход рамки снаружи

```julia
function walk_around_inner!(robot, act; skip_frame = false)
    act_here(side) = (skip_frame && on_frame(robot, side)) ? 0 : act(robot)
    total = 0
    for side in (Ost, Nord, West, Sud)
        move!(robot, side)
        while isborder(robot, left(side))     # слева от движения — стена рамки
            total += act_here(side)
            move!(robot, side)
        end
        total += act_here(side)               # угловая клетка
    end
    return total
end
```

```
   C3 ← ← ← ← ← ← ← C2        Старт — клетка S (диагональ от рамки, левее и ниже неё).
   ↓    ┌───────────┐  ↑      Идём: Ost (по низу), Nord (справа), West (сверху), Sud (слева).
   ↓    │   рамка   │  ↑      C1, C2, C3 — угловые клетки, они обрабатываются
   ↓    └───────────┘  ↑      в конце каждой стороны; четвёртый угол — сама клетка S.
   S → → → → → → → → C1
```

Принцип: движемся вдоль рамки, стена рамки всегда **слева** от направления движения (`left(side)`). Когда стена слева закончилась — мы в угловой клетке: обработать её и повернуть. Все клетки кольца обработаны ровно один раз, Робот возвращается в старт.

Параметр `skip_frame = true` (задача 11): клетки, которые лежат на внешней рамке, пропускаются, потому что уже учтены при обходе внешнего периметра (чтобы клетка, общая для обоих периметров, считалась один раз).

### 3.14. `on_frame(robot, side)`

```julia
on_frame(robot, side) =
    any(s -> s != left(side) && isborder(robot, s), (Nord, West, Sud, Ost))
```

«Эта клетка у внешней рамки?» Смотрим на все четыре стороны, **кроме** `left(side)` — там стена внутренней рамки, она нам не подходит. Если с любой другой стороны стена — клетка на внешней рамке.

### 4.1. Задача 1 — крест

**Условие.** Робот в произвольной клетке ограниченного поля без перегородок. Расставить маркеры в виде креста до внешней рамки. Центр без маркера. Робот возвращается.

**Ответ на «почему центр без маркера».** По условию в клетке с Роботом маркера нет — и `walk_to_frame!` вызывает `act` только после шага.

### 4.5. Задача 5 — внешняя и внутренняя рамки

**Условие.** Есть одна прямоугольная перегородка, не касающаяся рамки. Замаркировать периметр внешней рамки и периметр (снаружи) внутренней.

function task5!(robot)

### 4.13. Задача 13 — проход в бесконечной стене

**Условие.** Поле неограниченное. С направления `side` от Робота стоит перегородка — бесконечная прямая с **одним проходом в одну клетку** на неизвестном расстоянии. Пройти через проход.

```julia
function task13!(robot, side)
    d = left(side)              # направление очередного захода
    num_steps = 1               # длина очередного захода
    while isborder(robot, side) # пока стена перед нами
        for _ in 1:num_steps
            move!(robot, d)
            if !isborder(robot, side) break end    # проход найден — прекратить заход
        end
        d = inverse(d)          # развернуться
        num_steps *= 2          # удвоить длину захода
    end
    move!(robot, side)          # шагнуть в проход
end
```

**Идея — «челнок» с удвоением**: заходы длиной 1, 2, 4, 8… то влево, то вправо:

```
  стена ────────────────── ○ ─────────── (проход)
                          ←1
                      →2
                  ←4
          →8
```

Заходы последовательно «покрывают» всё более широкую область по обе стороны. Когда напротив Робота стена пропадает — мы напротив прохода. `break` прерывает заход сразу; `while` тоже заканчивается; шагаем в проход.

> [!question] Почему удвоение, а не +1?
> Если бы длина заходов росла как 1, 2, 3, 4…, то до прохода на расстоянии `d` потребовалось бы порядка `d²` шагов. При удвоении сумма длин всех заходов — **O(d)** (около `d` с небольшой константой): последний заход не больше, чем в 2 раза длиннее нужного, и все предыдущие вместе дают столько же. Это стандартная оценка для поиска «в неизвестном месте на прямой».

### 4.14. Задача 14 — маркер на пустом неограниченном поле

```julia
function move_until_marker!(robot, side, num_steps)
    for _ in 1:num_steps
        if ismarker(robot) break end
        move!(robot, side)
    end
end

function task14!(robot)
    side = Nord
    num_steps = 1               # длина двух очередных отрезков спирали
    while !ismarker(robot)
        for _ in 1:2
            move_until_marker!(robot, side, num_steps)
            side = left(side)
        end
        num_steps += 1
    end
end
```

**Идея — спираль.** Отрезки: север 1, запад 1, юг 2, восток 2, север 3, запад 3, юг 4, восток 4… Каждая пара отрезков имеет одинаковую длину, затем длина увеличивается на 1. Поворот — всегда налево (`left`).

```
 длины отрезков:  1 1 | 2 2 | 3 3 | 4 4 | ...
 направления:     N W | S O | N W | S O | ...   (O = Ost; всегда поворот налево)
```


**Тонкости:**

- Проверка маркера идёт **перед каждым шагом** внутри отрезка, плюс условие внешнего цикла. Поэтому Робот остановится ровно на маркере, а не пройдёт мимо.
- Спираль покрывает **каждую клетку** области вокруг старта, значит маркер обязательно будет найден (если он существует).
- Сложность: чтобы найти маркер на расстоянии `d`, надо пройти порядка `d²` шагов (площадь области). Это неизбежно: без знания направления нужно просмотреть всю область.

### 4.15. Задача 15 — маркер на поле с перегородками

**Условие.** Поле неограниченное, на нём есть перегородки — отрезки, **лучи** (бесконечные в одну сторону), прямоугольники. Найти маркер.

```julia
function task15!(robot)
    position = (x = 0, y = 0)
    prev_side, prev_target = Ost, 0     # предыдущий отрезок спирали
    target = 1                          # координата конца очередных отрезков
    while !ismarker(robot)
        for side in (Nord, West, Sud, Ost)
            position = move_leg!(robot, side, target, prev_side, prev_target, position)
            prev_side, prev_target = side, target
        end
        target += 1
    end
end
```

#### Что изменилось по сравнению с задачей 14

Перегородки могут перекрыть путь. Поэтому спираль строится **не по счёту шагов, а по координатам**: Робот помнит свою позицию `(x, y)` относительно старта, и каждый отрезок идёт до заданной координаты.

| Сторона | Идти, пока… |
|---|---|
| `Nord` | `y < target` |
| `West` | `-x < target` |
| `Sud` | `-y < target` |
| `Ost` | `x < target` |

После каждого полного оборота (4 стороны) `target += 1`.

#### Вспомогательные функции задачи 15

```julia
const DELTA = ((0, 1), (-1, 0), (0, -1), (1, 0))   # сдвиг (dx, dy) для Nord, West, Sud, Ost

delta(side) = DELTA[Int(side) + 1]

function go!(robot, side, position)                 # шаг + новая позиция
    move!(robot, side)
    dx, dy = delta(side)
    return (x = position.x + dx, y = position.y + dy)
end

function coord(position, side)                      # «координата вдоль направления side»
    dx, dy = delta(side)
    return dx * position.x + dy * position.y
end
```

- `DELTA` стоит в порядке значений `HorizonSide`, поэтому индекс — `Int(side) + 1` (в Julia индексы с 1).
- `coord(position, West)` = `-x`, `coord(position, Sud)` = `-y` — то есть всегда «насколько далеко мы ушли в сторону `side`».
- Позиция — **неизменяемый** кортеж; `go!` возвращает **новый**.

#### `step_bypass!` — шаг с обходом (самое сложное место)

```julia
function step_bypass!(robot, side, position)
    if !isborder(robot, side)
        return go!(robot, side, position)
    end
    d = left(side)
    num_steps = 1
    shift = 0                      # смещение вдоль перегородки (+ налево, − направо)
    while isborder(robot, side)
        for _ in 1:num_steps
            position = go!(robot, d, position)
            shift += d == left(side) ? 1 : -1
            if !isborder(robot, side) break end
        end
        d = inverse(d)
        num_steps *= 2             # «челнок», как в задаче 13
    end
    back = shift > 0 ? right(side) : left(side)
    position = go!(robot, side, position)       # обошли конец перегородки
    while isborder(robot, back)                 # вдоль стороны прямоугольника
        position = go!(robot, side, position)
    end
    for _ in 1:abs(shift)                       # вернуться на исходную линию
        position = go!(robot, back, position)
    end
    return position
end
```

Почему так сложно: в задаче 13 мы знали, что стена — бесконечная, а проход в **одну** клетку. Здесь перегородка может быть **лучом**: бесконечной с одной стороны. Если всегда обходить налево, Робот уйдёт в бесконечность. Поэтому конец ищем «челноком» (как в 13) — в обе стороны с удвоением. Это гарантирует, что мы найдём тот конец, который существует.

Шаги:

1. Стены нет → просто шаг.
2. Иначе «челнок» вдоль стены, считая `shift` (куда и насколько ушли).
3. Нашли конец → шаг мимо него → пока рядом (со стороны `back`) стена прямоугольника, идти вдоль.
4. Вернуться на исходную линию на `|shift|` шагов в направлении `back`.

#### `return_to_line!` и `move_leg!`

```julia
function return_to_line!(robot, prev_side, prev_target, position)
    while !ismarker(robot) && coord(position, prev_side) > prev_target &&
          !isborder(robot, inverse(prev_side))
        position = go!(robot, inverse(prev_side), position)
    end
    return position
end

function move_leg!(robot, side, target, prev_side, prev_target, position)
    position = return_to_line!(robot, prev_side, prev_target, position)
    while !ismarker(robot) && coord(position, side) < target
        position = step_bypass!(robot, side, position)
        position = return_to_line!(robot, prev_side, prev_target, position)
    end
    return position
end
```

- Обход прямоугольника может увести Робота **за** линию предыдущего отрезка (дальше, чем требовала спираль). `return_to_line!` возвращает его на неё (если не мешает стена и пока нет маркера).
- `move_leg!` идёт по текущему отрезку шагами `step_bypass!` до координаты `target` или до маркера.

> [!warning] Что говорить на защите про задачу 15
> Это самая сложная задача: она объединяет **спираль** (задача 14), **«челнок»** (задача 13) и **обход перегородок** (`move_bypass!`). Важно уметь объяснить три идеи: (1) спираль по **координатам**, а не по количеству шагов; (2) конец перегородки ищем челноком, потому что она может быть лучом; (3) после обхода возвращаемся на линию спирали.

## 5. Вопросы на защите и ответы

> [!question]- Почему функции возвращают именованные кортежи, а не структуры?
> По лекции 4 — без мутабельных структур. Кортеж неизменяем, поэтому нельзя случайно испортить результат; обращение `snake.total` читается так же ясно, как поле структуры.

> [!question]- Зачем `import HorizonSideRobots: move!`?
> Чтобы **добавить** метод к функции из чужого модуля. Без `import` определение `move!(robot, side, n)` создало бы **новую** функцию `Main.move!`, которая закрыла бы библиотечную.

> [!question]- Зачем передавать `act` в функцию?
> Один и тот же обход (крест, периметр, змейка) используется для двух разных действий — «поставить маркер» и «посчитать маркер». Без `act` пришлось бы писать каждый обход по два раза.

> [!question]- Почему `to_corner!` возвращает `num_west` и `num_south`, а не просто «позицию»?
> У Робота нет координат. Нужно записать путь (числа), чтобы потом вернуться. При этом `num_west` — число **вызовов** обхода, а `num_south` — высота исходного ряда.

> [!question]- Почему на пути «из угла обратно» `move_bypass!` вернёт Робота ровно в нужную клетку?
> Каждый обход перегородки возвращает Робота на ту же линию (ряд), с которой он начал. Все перегородки изолированы, поэтому обход всегда однозначен, и число вызовов совпадает.

> [!question]- Как в `move_bypass!` отличить внутреннюю перегородку от внешней рамки?
> Идём вдоль стены. Перегородка кончается (стена в `side` пропадает) — обходим. Если дошли до края поля, а стена всё ещё есть — это внешняя рамка; возвращаемся и сообщаем `0`.

> [!question]- Почему змейка не запоминает позицию Робота, а считает `x`?
> В ряду, где есть перегородка, идти до упора нельзя — упрёмся в перегородку, а не в рамку. Поэтому длина ряда известна заранее (`width` из нижнего ряда), а положение отслеживается числом `x`, которое меняется на `k` — продвижение при каждом обходе.

> [!question]- Почему на подъём на следующий ряд хватает обычного `move!`?
> Подъём происходит у края поля (в крайнем столбце), а крайние столбцы свободны: перегородки не касаются внешней рамки.

> [!question]- Можно ли найти маркер быстрее, чем по спирали в задаче 14?
> Нет: направление неизвестно, значит, нужно просмотреть все клетки в радиусе `d`. Их порядка `d²`. Спираль делает ровно это без повторных проходов.

> [!question]- Почему в задаче 13 заходы удваиваются?
> Чтобы суммарный путь был **O(d)**, а не **O(d²)**. Каждый заход в два раза длиннее предыдущего; последний заход по длине сравним с `d`, все предыдущие вместе — столько же.

> [!question]- Чем задача 15 отличается от задачи 14?
> Есть перегородки. Поэтому: (1) позиция хранится как координаты, (2) шаг делается через `step_bypass!` (с обходом), (3) после обхода Робот возвращается на линию спирали.

> [!question]- Зачем нужны утверждения (`#УТВ`) и инварианты?
> Это способ доказать корректность: утверждение — что истинно в данной точке программы; инвариант — что истинно перед каждой итерацией цикла и после. Если инвариант + условие выхода из цикла дают нужный результат — программа верна.

> [!question]- Что будет, если вызвать `move!` в стену?
> Ошибка выполнения. Поэтому перед каждым шагом либо проверяем `isborder`, либо знаем из условия, что путь свободен.

> [!question]- Как проверить, что решения правильные?
> Файл `test_all.jl` генерирует случайные поля (перегородки, маркеры, стартовые позиции) и проверяет результаты каждой задачи. Для визуальной проверки — `julia solutions/taskNN.jl` (анимация на примере из `fields/`).

## 6. Шпаргалка

### Три обхода

| Обход | Откуда | Где `act` | Возврат |
|---|---|---|---|
| `walk_kross!` | центр | после шага | на `num_steps` назад |
| `walk_perimeter!` | юго-западный угол | до шага | сам попадает в угол |
| `walk_snake!` | юго-западный угол | после шага | `back_from_snake!` |

### Каркас решения

```julia
function taskN!(robot)
    num_west, num_south = to_corner!(robot)       # 1. в угол
    ...обход с act...                             # 2. работа
    from_corner!(robot, num_west, num_south)      # 3. назад
end
```

### Что за что отвечает

| Функция | Одной фразой |
|---|---|
| `inverse / left / right` | повороты через арифметику по модулю 4 |
| `move!(robot, side, n)` | n шагов подряд |
| `move_to_frame!` | идти до упора |
| `walk_to_frame!` | идти до упора с `act` |
| `along_wall!` | идти вдоль стены до её конца |
| `pass_wall!` | обойти конец перегородки и вернуться на линию |
| `move_bypass!` | шаг с обходом (возвращает продвижение, 0 — рамка) |
| `to_corner!` | в юго-западный угол, запомнив путь |
| `from_corner!` | вернуться по запомненному пути |
| `walk_snake!` | обойти всё поле рядами |
| `move_to_inner_frame!` | найти внутреннюю рамку |
| `walk_around_inner!` | обойти внутреннюю рамку снаружи |

### Идеи в одну строку

1. **1, 7** — четыре луча «туда-обратно».
2. **2, 3, 8, 9** — угол → периметр → назад.
3. **4, 6, 10, 12** — угол → змейка → назад.
4. **5, 11** — периметр + найти рамку + кольцо вокруг неё.
5. **13** — челнок с удвоением.
6. **14** — спираль с одинаковыми парами отрезков.
7. **15** — спираль по координатам + челнок + обход перегородок.

### Сложность

| Задача | Шагов Робота |
|---|---|
| 1, 7 | порядка `W + H` |
| 2, 3, 8, 9 | порядка `W + H` |
| 4–6, 10, 12 | порядка `W · H` |
| 5, 11 | порядка `W · H` (поиск рамки змейкой) |
| 13 | `O(d)` |
| 14 | `O(d²)` |
| 15 | `O(d²)` с обходами |

`W`, `H` — размеры поля, `d` — расстояние до цели.
